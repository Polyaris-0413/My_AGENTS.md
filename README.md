# 全局开发规范

> 若本文件与已安装 Skills 的规则之间存在冲突，应以本文件为准；冲突时仅让位冲突部分，不得因局部冲突而整体舍弃其余规则。

> 未经允许禁止修改 AGENTS.md 文件，该文件应由人工修改。

## 1. 沟通

- 思维链与正文应使用中文。

## 2. 减少冗余

实现功能前先检索项目内可复用代码：

1. 有可复用代码：直接调用。
2. 调用不便：先封装，再调用。
3. 无现成代码：按以下优先级选择实现手段：
   - 语言/框架原生 API
   - 成熟第三方库
   - 自行实现

## 3. 长期思维

- 运行时确定的值，应写自适应逻辑处理，不得硬编码。
- 编写自然语言规则时，应确保规则具有足够的通用性和实质性作用；包含例子的规则无法证明其具有通用性。
- 若用户未说明具体技术方案，应自行采用最适合项目的标准化方案。

## 4. 注释

- 注释应仅写代码无法表达的原因与出处；不得“达到预期”式复述代码行为，不得保留与代码不符的注释。
  > 原因只写结论，不写推导过程。

- 不得写没有防错价值的注释。

## 5. 漏洞修复

- 优先从源头修复问题；当无法从源头修复而必须打补丁时，补丁效果应覆盖所有同类变体，不得只针对当前样本。

## 6. 设计

- 所有设计类取值应来自项目统一的设计源，代码只引用，不得另行定义。
  > 设计源包括项目所采用的公共设计语言规范  
  > 若项目尚无设计源，应先建立最小设计源再实现功能。

## 7. 交付

### Android

- 每次交付后应编译、安装并在真机上并打开。

## 8. 备份

- 在每次代码修改后，应使用 git 进行备份。
- 回滚代码时，应使用 git 复原。

## 9. 文件

- 由 agent 生成的文件应分类存放至 `C:\Users\Administrator\ai_workspace` 路径下，另有明确指定存放路径的除外。

> 若无复用价值，应在完成任务直接删除。
